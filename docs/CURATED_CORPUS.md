# accepted-v1・weak-v1データセット

## 目的

`accepted-v1`は、やる夫AA録2 v32.1から人が完成AAとして採用した最初の100件を固定したローカルコーパスです。元MLTの配布・機械学習・再配布条件は未確定のため、Gitや配布物へ含めず`unknown; local curation only`として扱います。

同じスナップショットには不採用217件も`negative_pool`として保存します。これは生成モデルの正解ではなく、品質順位モデルの負例です。

## 再生成

レビューDBの採用数がちょうど100件の状態で、次を一度実行します。出力先が空でない場合は上書きしません。

```powershell
.\.venv\Scripts\python.exe -m training.freeze_review_corpus
.\.venv\Scripts\python.exe -m training.audit_review_snapshot
```

生成先はGit対象外の次の場所です。

```text
datasets/incoming/yaruyomi/v32.1/accepted-v1/
├─ snapshot.json
├─ records.jsonl
├─ audit.json
└─ aa/
   ├─ train/
   ├─ validation/
   ├─ test/
   └─ negative_pool/
```

`records.jsonl`には、原本パス、MLTチャンク、原本本文ハッシュ、Unicode本文ハッシュ、文字参照変換、採否、完成度、修正カテゴリ、題材タグ、split、権利状態を記録します。`snapshot.json`はマニフェスト自体のSHA-256を保持します。

## 固定結果

| 項目 | 件数 |
| --- | ---: |
| 全レビュー | 317 |
| 採用 | 100 |
| 不採用 | 217 |
| 採用元MLT | 75 |
| sensitive題材 | 11 |
| train | 80件・62 MLT |
| validation | 10件・6 MLT |
| test | 10件・7 MLT |

splitは修正カテゴリの分布を近づけながら、同じMLTを必ず一つのsplitだけへ割り当てます。監査では本文ハッシュ不一致、空白だけが異なる重複、4-gram重複88%以上の小差分、左右反転近似、split間のMLT重複はいずれも0件でした。

背景4件、複数人物4件、小物3件、メカ2件などの少数カテゴリはtrainだけに存在します。これは分割漏洩を起こしてまで全splitへ複製せず、カテゴリ別の最終評価には追加収集が必要であることを明示するためです。

## 品質順位ベースライン

採用100件と不採用217件から、採点・採否を特徴へ混ぜず、本文の寸法、文字種比率、行構造、暫定カテゴリなど45特徴でRandom Forestを学習します。

```powershell
.\.venv-training\Scripts\python.exe -m training.train_quality_ranker
```

出力は`.tmp/training-runs/quality-ranker/`です。source MLT単位の5-fold未見評価結果は次のとおりでした。

| 指標 | 結果 |
| --- | ---: |
| 無作為の採用率基準 | 0.315 |
| ROC-AUC | 0.588 |
| Average precision | 0.413 |
| 上位100件の適合率 | 0.400 |

基準より信号はありますが、自動採用やレビューキューの置換には弱すぎます。このモデルは比較基準として保持し、運用へは接続しません。次の品質モデルではSaitamaar再描画画像、局所構造、疑似線画への人手評価を追加します。

## weak-v1疑似線画

採用100件からカテゴリを巡回して20作品を選び、各4候補を決定的に生成します。

```powershell
.\.venv\Scripts\python.exe -m training.generate_weak_pairs
```

生成先は`datasets/incoming/yaruyomi/v32.1/weak-v1/`です。

- `skeleton`: Saitamaar字形の細線化
- `contour`: 平滑化後のCanny輪郭
- `simplified`: 接続、小成分除去、細線化
- `dropout`: 細線化後にseed固定の部分欠落と小成分除去

20作品×4方式の80候補について、入力AAハッシュ、Saitamaarハッシュ、方式、全設定、seed、画像ハッシュを`pairs.jsonl`へ保存します。全12カテゴリを含みます。

これらは実在した元画像や作者の線画ではありません。特に`skeleton`と`contour`は文字の輪郭を強く残します。`simplified`と`dropout`も選好候補であり正解線画ではないため、`weak_pair`以外の名前で学習正解へ昇格させません。

## 選好レビュー

weak-v1の20作品と各4候補は、当時のブラウザ用ブラインドレビューで評価しました。現役レビュー機能は評価終了後に削除済みです。既存の評価DB `weak-v1/preferences.sqlite3`、候補画像、`pairs.jsonl`は失敗実験の監査証拠として変更せず保持します。

20作品・80候補の初回評価は完了しました。専用再集計コマンドは現役レビュー機能とともに削除し、確定した結果を以下へ固定しています。既存の集計JSONはローカル監査資料として残します。

| 方式 | 最良選択 | 構造保持平均 | 線品質平均 | 脱・文字感平均 |
| --- | ---: | ---: | ---: | ---: |
| skeleton | 18 | 4.70 | 4.75 | 4.80 |
| contour | 0 | 0.15 | 0.15 | 0.15 |
| simplified | 0 | 2.75 | 2.80 | 2.55 |
| dropout | 2 | 3.90 | 3.95 | 3.85 |

「どれも不可」、同点、問題タグ、コメントは0件でした。80候補中72候補では3軸が完全に同じ点数で、3軸別の信号より総合的な良し悪しとして採点された傾向があります。最良選択と3軸合計の単独最高は16/20件で一致し、残る4件は主に合計点の同点です。

評価者の事後説明により、細線化へ18/20件が偏った主因は脱文字や線品質ではなく、4候補中で塗り領域を実質的に保持していたことだと判明しました。部分除去以外の方式は塗り・濃淡を大きく失っており、旧3軸には塗り保持がありませんでした。このためweak-v1は方式の優劣を示す成功した選好実験ではなく、「塗り保持を評価設計から落とすと選択が一方式へ交絡する」ことを確認した失敗パイロットとして扱います。細線化18件という値を脱文字性能や本番採用の根拠には使いません。

AA字形を細線化しただけの入力は出力文字への近道を残すため、この20件から方式名を覚える報酬モデルは作りません。`skeleton`は勝者ではなく「塗りは残るが字形リークも最大」の比較対照としてだけweak-v2へ残します。

## weak-v2ブラインド比較

weak-v1と同一の20作品を使い、次の6候補・計120画像を`datasets/incoming/yaruyomi/v32.1/weak-v2/`へ生成します。

```powershell
.\.venv\Scripts\python.exe -m training.generate_weak_pairs_v2
```

| 内部方式 | 目的 |
| --- | --- |
| `skeleton` | weak-v1の勝者を固定比較基準にする |
| `tone_density` | 細かい局所インク密度を連続グレースケールへ変換する |
| `tone_density_coarse` | 文字・行ピッチより広く平滑化し、面の濃淡分布を残す |
| `tone_quantized` | 粗い濃淡分布を5段階へ量子化し、塗り領域を明確にする |
| `tone_contour` | 粗い濃淡分布に、その面境界から抽出した輪郭を重ねる |
| `warped_tone` | 字形を滑らかに変形してから濃淡分布と面境界を作る |

候補方式は画面に表示せず、作品IDと方式名から作った安定ハッシュ順で「候補A～F」へ割り当てます。同じ作品を開き直すと順序は変わりませんが、全作品で特定方式が同じ位置にはなりません。評価は`weak-v2/preferences.sqlite3`へ保存し、完了済みのweak-v1評価を変更しません。

最良候補は、まず構造保持と塗り・濃淡保持を必須条件として判断し、その条件を満たす候補間で字形リーク抑制を比較します。塗りを消した結果として個々の文字が読めなくなった候補を、高い脱文字性能とは数えません。

この段階でも6候補は実在元絵ではなく、幾何・濃淡事前学習用の弱い疑似入力です。weak-v2の目的は「細線化そのまま」より文字字形の近道を減らしつつ、完成AAの構造と塗り・陰影分布を保つ変換があるかを同一作品内で検証することです。脱文字だけを目的にして塗りを失う候補は採用しません。

## accepted-v2収集基盤

現行レビューは旧317件と完全に独立した`reviews-v2.sqlite3`へ保存する。旧提示履歴、採否、カテゴリ修正、近似判定を候補選定へ読み込まず、同じAAが現れてもv2で新しく判定する。候補は50件単位の決定的キューへ固定し、次は750 acceptedとカテゴリ最低数の両方へ向けて不足を優先する。カテゴリ別の実採用率で提示配分を補正し、通常は同一MLT最大3件とするが、全原本が上限へ達した不足カテゴリだけ提示回数を均等に広げる。サイズは順位付けだけに使い、硬い最小行数・列数・文字数では除外しない。完全・空白差の同一本文だけを再提示せず、改変・派生AAは個別に評価する。近似系列はsnapshot作成時に同じsplitへ束ね、学習上の冗長性が問題になる場合だけ品質と被覆を比較して片方を除外する。最終学習件数を節目の数字へ揃えるための補充はしない。

250件の継続監査と500件の初回学習監査は`checkpoints/0250`、`checkpoints/0500`へ固定済みです。次の750件以上・カテゴリ最低数達成checkpointは次で固定・監査します。出力先が空でない場合は上書きしません。

```powershell
.\.venv\Scripts\python.exe -m training.freeze_review_corpus_v2
.\.venv\Scripts\python.exe -m training.audit_review_snapshot --snapshot datasets\incoming\yaruyomi\v32.1\accepted-v2\checkpoints\0750
.\.venv\Scripts\python.exe -m training.audit_review_checkpoint --snapshot datasets\incoming\yaruyomi\v32.1\accepted-v2\checkpoints\0750 --target-accepted 750 --baseline datasets\incoming\yaruyomi\v32.1\accepted-v2\checkpoints\0500
```

### weak-v2評価結果と逆変換ペアの中止判断

20作品・120候補のブラインド評価は完了しました。方式別の平均点は次のとおりです。

| 方式 | 最良選択数 | 構造保持 | 塗り・濃淡保持 | 字形リーク抑制 | 判定 |
| --- | ---: | ---: | ---: | ---: | --- |
| `skeleton` | 2 | 5.00 | 5.00 | 0.00 | 元AAをほぼ残した対照であり、入力教師には使えない |
| `tone_density` | 16 | 3.00 | 3.00 | 3.60 | 相対的には最良だが、ぼかしが強く実用不可 |
| `tone_density_coarse` | 2 | 1.20 | 1.15 | 4.20 | 原型の多くを失う |
| `tone_quantized` | 0 | 0.00 | 0.00 | 5.00 | 原型を失う |
| `tone_contour` | 1 | 0.15 | 0.15 | 4.95 | 原型を失う |
| `warped_tone` | 0 | 0.00 | 0.00 | 5.00 | 原型を失う |

最良選択数の合計が20を超えるのは、1作品で同点選択があるためです。評価画面上の「全候補不適切」は選ばれませんでしたが、評価後の総括では6方式すべてが学習入力として不適切と判断されました。したがって、`tone_density`の16件は採用率ではなく、使えない候補群の中での相対順位です。

この失敗は旧1ch候補の単なるパラメータ不足とは扱いません。完成AAでは、元の構造と濃淡が文字単位の字形・配置そのものに符号化されており、1枚の画像で字形だけを壊すと構造と濃淡も失われます。このため同系統のweak-v3は作りません。外部設計v1.1の`Eはch0だけ、ch1はAAラスタから直接`という多チャンネル経路はP6まで実測し、当時の低周波`ch1`定義は合成testの改善に対して実画像で誤塗りしたため不採用になりました。ただし、線と塗り・面を別々に逆生成するDeepAA型経路全体を不採用にした結果ではありません。次はaccepted-v2から分離チャンネルを作る新設計として再開します。

ただし、weak-v1の`dropout`は人物1件とエフェクト1件で最良に選ばれ、20件平均でも構造保持3.90、線品質3.95でした。評価者の事後説明では、選択数が2件に留まった主因は線品質ではなく塗り欠落です。その後の合成確認では必要線もランダムに欠落したため、`dropout`処理自体は採用しません。この結果は「線と塗りを別信号で扱う」必要性を示した比較資料としてだけ残します。AA逆変換画像を正解元絵と見なさない点は変わりません。

追加の6作品プレビューでは、`dropout`線を最前面に固定し、その下へ連続濃淡、段階塗り、密集部塗り、粗い領域塗りを合成しました。しかし、塗り側は文字の局所密度しか観測できないため、意味上は白い領域を塗り、必要な塗りを外しました。線側も`dropout`のランダム部分除去により必要線を失いました。線を塗り境界として使う追加案は文字ごとの白抜きを強調しました。このため合成方式も不採用とし、比較UI、API、生成コードは現行機能から削除しました。

ここで画像密度だけでなくAA本文の構造を確認し、`.`、`:`、`;`など同じ濃淡文字が横に連続する箇所を塗りとして抽出する方式を追加しました。罫線、格子、斜線は塗りから除外します。全100作品のうち78作品で反復塗りを検出しました。残る22作品には複数文字を混ぜた網掛けがあるため、現方式の適用外として明示します。生成した線・塗りラベルは、多チャンネル自己教師と直接対応対の出力側補助ラベルに使用します。

`accepted-v1`の100作品は破棄せず、過去実験の再現に使用します。次の主コーパスは全索引から判定を新規に行う`accepted-v2`です。250 acceptedごとに不変snapshotを作り、500件を最初の本格学習地点、750～1,000件以上を準備規模として、カテゴリ・MLT・文字・実幅・塗り面・網掛けモチーフと学習性能が飽和するまで250件ずつ拡張します。500件を固定終了数にはしません。AA本文の文字列事前分布、部品検索、文字接続、配置候補、塗り・網掛けパターンに加え、線chと塗り・面chを別々に逆生成して元AAを正解とするDeepAA型自己教師へ使用します。実画像ではP6R-G1とのA/Bと安全指標を先に使い、人が直す直接対応対は正解対応なしでは原因を分離できない少数例だけの任意監査にします。

0500 snapshotの線・塗り分離逆変換v1は完了しました。P6R-1単一文字面Aと複数文字周期面を加えるBの両方を保存し、500/500件で元描画への可逆性、Saitamaar行幅、面ID整合・連結、二重生成のbyte決定性を確認しました。Bは476作品・524,041文字へ面を付け、Aとの差分最大24件の目視でも主要輪郭や台詞の大量な誤分類は見つからなかったため、次のモデル設計候補はBです。400観測モチーフのうち複数作品支持フラグは30種で、低支持モチーフを学習でどう扱うかは未承認です。詳細は[0500逆変換監査](REVERSE_CHANNELS_V1.md)を参照してください。
