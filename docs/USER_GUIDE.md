# Yaruo AA Studio 操作ガイド

この資料は、画像から編集可能なやる夫系Shift-JIS AAの下書きを生成し、仕上げへ持っていくための実用手順です。

Yaruo AA Studioは完成AAを無修正で自動生成する道具ではありません。画像の構造をSaitamaarの字形へ置き換え、最後に人が直せるテキスト下書きを作ることを目的としています。

## 1. 起動

依存関係とフロントエンドが準備済みなら、リポジトリ直下で次を実行します。

```powershell
.\run.ps1
```

コンソールに表示される `http://127.0.0.1:8000/` をブラウザで開きます。終了するときは、起動したPowerShellで `Ctrl+C` を押します。

画面側も変更しながら開発する場合は、代わりに次を使います。

```powershell
.\start.ps1
```

## 2. 基本操作

1. 「画像をドロップ」へ画像を置くか、クリックして選択します。
2. 入力に合う「抽出」プロファイルを選びます。
3. 「構図」で必要な範囲を切り出します。
4. 「AAを1案生成」を押します。
5. `EXTRACTED LINES` で、AAに残したい線が抽出されているか確認します。
6. `SAITAMAAR RENDER` で、文字として再描画した結果を確認します。
7. 必要な場合だけ「AAエディタ」で局所的に修正します。厳密な修正対応対を残す場合は「修正対を保存」を押し、「Unicodeコピー」「CP932/NCRコピー」または「TXT保存」で取り出します。

「累積改善」は初期状態でONです。人物・背景などの色画像では、P6R-4Lの回収線とP6R-3/4の索引付き面を別チャンネルでLSモデルへ渡し、学習済みの文字開始位置と1,187文字から実幅どおりに生成します。モデル読込・推論・実幅・白紙化の安全条件に失敗した場合は、従来のP6R-G1累積生成全体へ戻ります。OFFにすると比較・再現用の旧DeepAA生成になります。線画・背景線画プロファイルはtone面を持たないため、ONでもP6R-G1の線画経路を使います。LS暫定版はCPUで旧経路より時間がかかることがあります。

`ORIGINAL`には、現在の「左・上・幅・高さ」で実際に使用される範囲を黄緑色の枠で常時表示します。枠外は暗く表示され、プリセットやスライダーを変更すると生成前にその場で追従します。画像端を越える幅・高さは、変換時と同じ規則で画像内へ制限して表示します。

「行数自動」は初期状態でONです。現在の切り抜き範囲、横幅、Saitamaarの半角セル幅8px・行ピッチ18pxから、元画像の縦横比を崩さない最大行数を自動計算します。「左」「上」は通常は行数を変えませんが、切り抜きが画像端を越えて幅・高さが制限される場合は計算へ反映されます。任意に縦を詰めたい場合はOFFにし、最大行数を手動で指定してください。

「Unicodeコピー」とTXT保存はUnicodeをそのまま扱い、TXTはUTF-8です。「CP932/NCRコピー」は、CP932で表現できない文字だけを10進数値文字参照（例: `&#9608;`）へ変換します。これはMLTなどのCP932テキストで保存・受け渡すための表現です。画面では常に復元後のUnicodeを表示します。現在の生成候補はCP932文字中心ですが、手編集や今後の文字集合拡張でも同じ規則が使えます。

数値文字参照はHTMLのUnicode対応に必要なのではなく、今回の旧来データ形式でCP932外文字を保持するために使います。HTMLソースへ直接埋め込む場合は、この変換とは別に`&`や`<`などのHTMLエスケープが必要です。

完了したv2～v4比較収集のボタンと候補選択UIは、通常のAA生成画面から撤去済みです。保存済み記録と再現用APIは実験証拠として維持します。

P6R-4T2/T3の固定5件A/B収集も完了しており、その一時ボタンと候補選択UIは撤去済みです。保存済みv5/v6記録と再現用APIは実験証拠として維持します。T3は正式品質合格ではありませんが、現状で適用できる範囲を失わないため、累積改善ONの最終段に版付き・安全fallback付きで暫定利用します。パターン集合を増やした後に再集計して置き換える予定です。

### 修正対応対の保存

AAを生成した後、AAエディタの文字を一つ以上修正すると「修正対を保存」が有効になります。保存先はローカルの`datasets/incoming/correction-pairs/v1/`で、Gitや配布物には入りません。元画像、実際に使った正規化済み設定とクロップ、抽出線、修正前後のAAと再描画、座標変換、文字差分に加え、生成recipe、LS/P6R-G1 fallback来歴、LSのONNX・語彙・元checkpointハッシュを保存します。同じ内容をもう一度保存しても同じ記録を返します。

UIは権利状態を`user-provided; local use only; redistribution not granted`として記録します。これは元画像や修正AAの利用許諾を新たに与える表示ではありません。自分に利用権のある画像だけを使い、外部公開や学習済み重みの配布前には個別に確認してください。

### AAエディタと候補文字パレット

AAエディタは、元画像・抽出線・再描画と並べて見やすいようSaitamaar 12pxで表示します。これは編集画面だけの縮小表示です。変換、保存されるAA本文、修正対応対の座標、`SAITAMAAR RENDER`は引き続き正本のSaitamaar 16px・18px行ピッチを使います。

エディタ上部の候補文字パレットでは、現在のAAで使用頻度が高い文字と、基本線、接続、曲線、濃淡、AA部品、空白調整用のCP932文字をカテゴリ別に選べます。文字をクリックするとカーソル位置へ挿入し、エディタ内で範囲を選択している場合はその範囲を置き換えます。半角空白と全角空白は幅を見分けられる名前付きボタンです。

「元絵トレース」をONにすると、変換時に実際に使ったクロップ範囲の元画像をAA座標へ縮小し、編集欄の文字の背面へ重ねます。「透過度」は0%で元絵を不透明、100%で元絵を非表示にします。背景は編集欄と一緒にスクロールし、表示上だけの補助なので、AA本文、コピー、TXT、修正対応対の画像へは焼き込まれません。

## 3. 入力画像の選び方

### 人物・イラスト

- 顔、髪、輪郭の明暗差がはっきりした画像が向いています。
- 背景や服の模様が細かすぎる場合は、顔・上半身だけをクロップします。
- 顔が小さい全身絵は、顔のパーツがAAの1セル未満になりやすいため不利です。

### 完成線画

- 白地に黒線、またはそれに近い画像が向いています。
- アンチエイリアスは使用できますが、網点、鉛筆のざらつき、色付き背景は事前に減らした方が安定します。
- `線画` プロファイルではCannyによる二重輪郭化を避け、二値化した線を直接使います。

### 背景

- 建物の外形、屋根、窓、道路など、長い構造線が見える画像が向いています。
- 草木、砂利、雲などの細かいテクスチャは、そのままでは文字の塊になりやすいため弱めに抽出します。
- 背景は情報量が多いので、100～120字程度の横幅を推奨します。

## 4. プロファイル

| プロファイル | 用途 | 主な処理 | デフォルメ既定値 |
| --- | --- | --- | ---: |
| 自動 | 種別が明確でない画像 | 平滑化、局所コントラスト補正、輪郭抽出 | 30 |
| 人物 | 顔・上半身・キャラクター | 細い輪郭と主要輪郭を併用し、顔領域を保護 | 40 |
| 背景 | 建物・風景・室内 | 輪郭抽出に長直線検出を加える | 15（実質無効） |
| 線画 | すでに整理された白黒線画 | 二値化した元線を直接利用 | 35 |
| 背景線画 | 建築・風景の密な完成線画 | 密集模様を構造輪郭へ縮約し、長い線分を戻す | 35 |

プロファイルを切り替えるとデフォルメの推奨値も切り替わります。他の設定は必要に応じて手動で調整します。背景の既定値15は、内部のプロファイル係数を掛けると処理開始しきい値未満になるため、現在の実装では実質的にデフォルメなしです。背景で弱く適用したい場合は17以上から試します。

## 5. 構図プリセット

| プリセット | 想定 | 主な設定 |
| --- | --- | --- |
| 全体 | 画像全体を使う | クロップを全範囲へ戻す |
| 顔・上半身 | 配置済み人物サンプルに近い構図 | 中央64%幅、上側61%高を72字で処理 |
| 顔 | 顔だけを優先 | 中央42%幅、上側36%高を72字で処理 |
| 背景 | 背景全体 | 120字、最大60行、背景向け抽出値 |

プリセットのクロップ値は一般的な人物検出ではなく、現在のサンプルを基準にした初期値です。元画像に合わせて「左」「上」「幅」「高さ」を調整してください。各値は元画像に対する0～1の比率です。
クロップスライダーは0.005刻み・小数3桁表示です。「顔・上半身」プリセットの上位置0.015も、表示確認と手動再設定の両方ができます。

## 6. 設定項目

| 項目 | 意味 | 上げた場合の傾向 | 調整の目安 |
| --- | --- | --- | --- |
| 横幅 | 1行に確保する半角文字数 | 細部を表現しやすいが、表示幅と計算量が増える | 人物72～90、背景100～120 |
| 行数自動 | 切り抜き比率と横幅から最大行数を計算 | 縦横比を保ち、横幅変更にも追従する | 通常はON。意図的に縦を詰める場合だけOFF |
| 最大行数 | 縦方向の上限 | 縦の細部を保持しやすい | 行数自動OFF時に掲載先へ合わせる |
| 細部 | 高周波成分を残す量 | 細線や模様が増える | 線が欠けるなら上げ、ざらつくなら下げる |
| デフォルメ | AAセルより細かい密集線の整理量 | 線が減り、近接線が代表線へまとまる | 人物30～45、線画25～45、背景は無効の15または17～25 |
| 輪郭下限 | Canny輪郭抽出の下側しきい値 | 弱い線が減る | ノイズが多いとき上げる |
| 輪郭上限 | Canny輪郭抽出の上側しきい値 | 強い線だけを採りやすくなる | 主要輪郭まで消えない範囲で上げる |
| ノイズ除去 | 除去する連結成分の最小面積 | 小さい点や短線が減る | 点状ノイズが多いとき上げる |

`線画` プロファイルでは、輪郭しきい値よりも入力の白黒濃度、細部、デフォルメの影響が大きくなります。

## 7. 症状別の調整

### 全体が黒く、文字で塗り潰したように見える

1. `EXTRACTED LINES` がすでに濃いか確認します。
2. デフォルメを5～10上げます。
3. 細部を5～15下げます。
4. ノイズ除去を少し上げます。
5. 人物なら背景をクロップから外します。

抽出線が疎なのにレンダリングだけ濃い場合は、前処理ではなく文字選択側の問題です。設定を大きく崩すより、同じ条件の結果を品質評価へ追加してください。

### 輪郭や目・口が消える

1. 細部を上げます。
2. デフォルメを下げます。
3. ノイズ除去を下げます。
4. 顔を大きくクロップするか、横幅を増やします。
5. 人物・線画プロファイルを使います。

現在の顔保護は、人物・線画プロファイルでクロップ内の中央上部に顔があることを仮定しています。横顔、複数人物、極端な構図では保護位置が合わない場合があります。建築線画には、顔保護を行わない `背景線画` を使います。

### 線が二重になる

完成線画なら `線画` プロファイルへ切り替えます。通常画像で発生する場合は、細部を下げるかデフォルメを上げます。

### 右端がずれる、AAの形が崩れる

- 閲覧・編集にはSaitamaarを使います。
- プロポーショナルフォントや別の行間では、文字幅と行位置が一致しません。
- 本アプリの確認画像はSaitamaar 16px、行ピッチ18pxで生成されます。
- サクラエディタ等では自動折り返しを無効にし、タブを混ぜないでください。

### 処理が重い

- 横幅と最大行数を下げます。
- 先に必要範囲だけクロップします。
- 通常利用では既定の `beam` デコーダを使います。
- Viterbi系は品質実験用で、処理時間が増えます。

## 8. CLIで使う

一括変換や固定条件での比較にはCLIを使います。
以下の例で使う画像はリポジトリに同梱されません。手元の画像へパスを置き換えるか、[`samples/README.md`](../samples/README.md) に従ってローカルに配置してください。

### 線画

```powershell
.\.venv\Scripts\python.exe -m backend.cli .\samples\person-01-lineart.png `
  --output .\output\sample-lineart `
  --profile lineart `
  --columns 80 `
  --max-rows 58 `
  --detail 72 `
  --abstraction 35
```

### 人物の顔・上半身

```powershell
.\.venv\Scripts\python.exe -m backend.cli .\samples\person-01-source.png `
  --output .\output\sample-person `
  --profile person `
  --columns 72 `
  --max-rows 55 `
  --abstraction 40 `
  --crop 0.2 0.015 0.64 0.61
```

### 背景

```powershell
.\.venv\Scripts\python.exe -m backend.cli .\samples\background-01-source.png `
  --output .\output\sample-background `
  --profile background `
  --columns 120 `
  --max-rows 60 `
  --detail 58 `
  --abstraction 15 `
  --low 65 `
  --high 170 `
  --min-component 14
```

### 背景の完成線画

```powershell
.\.venv\Scripts\python.exe -m backend.cli .\samples\background-01-lineart.png `
  --output .\output\sample-bg-line-final `
  --profile background_lineart `
  --columns 120 `
  --max-rows 20 `
  --detail 58 `
  --abstraction 35 `
  --min-component 10
```

密な背景線画では行数を増やすほど建材や植栽の模様まで文字化されます。まず20行前後で全体のシルエットを確保し、必要な場合だけ行数を増やします。

CLIは出力先へ次の3ファイルを保存します。

- `<元名>.txt`: 編集可能なUTF-8のAAテキスト
- `<元名>-edges.png`: AA化に渡した抽出線
- `<元名>-aa.png`: Saitamaarで再描画した確認画像

`--decoder` には `beam`、`viterbi`、`viterbi-pruned` を指定できます。通常は `beam` を使い、他の2つは固定評価用に使います。

## 9. 品質確認

次の順で確認すると、原因を切り分けやすくなります。

1. 元画像の必要な構造がクロップ内にあるか。
2. 抽出線に目、口、顔輪郭、建物の主要線が残っているか。
3. AAレンダリングが抽出線の方向と位置を追っているか。
4. 同じ濃い文字が長く反復していないか。
5. テキストを局所修正して完成できる程度か。

固定サンプルの機械評価は次で実行できます。

```powershell
.\.venv\Scripts\python.exe -m evaluation.run
```

評価値だけでは「顔に見える」「建物に見える」は判定できません。最終判断には抽出線、レンダリング、Saitamaar上のテキストを併用します。

## 10. 現在の制限

- 意味を理解して線を描き直す生成モデルではありません。
- 顔保護は顔検出ではなく、中央上部の楕円領域を使う規則ベース処理です。
- 複数人物、手指、細かい装飾、植物などは潰れるか過密になりやすいです。
- 完成AAには、目、口、輪郭の接続や空白を人が調整する工程が必要です。
- 元画像と正解AAの対が増えれば、前処理や文字配置モデルを追加学習して改善できます。
