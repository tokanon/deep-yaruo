## 目的

P6R-4Lは現行案との比較で5/5合格したが、元絵に描画情報があるのにAAでは真っ白になる領域が残った。これは出力文字を単に濃くする問題ではない。元画像、選択候補のprocessed画像、面マスク、Saitamaar再描画を同一座標で比較し、どの段階で情報が落ちたかを診断する。

## 監査方法

保存済みv3記録と全artifactのSHA-256を検証してから、8px×18pxのDeepAA半角セル格子へ揃えた。元画像のクロップをprocessed画像と同じ大きさへ縮小し、各セルについて次を測った。

- 輪郭根拠: 平滑化後Sobel勾配のセル平均が画像内正値のP70以上かつ4.0以上
- テクスチャ根拠: 元画像とσ3局所平均の絶対差が画像内正値のP70以上かつ2.0以上
- 濃淡根拠: クロップ内グレースケールP10/P90で正規化した相対暗度のセル平均が0.18以上
- 出力空白: 再描画のインク被覆率が1%以下
- processed構造あり: 二値線被覆率が1%超
- 選択面あり: 面マスク被覆率が25%以上

輪郭・テクスチャ・濃淡のいずれかに根拠があり、出力が空白のセルを診断対象にした。原因はパイプライン順で排他的に、前処理構造消失、面候補または面判定欠落、選択済み面の配置欠落、文字化損失へ分類した。これは元絵の意味ラベルではなく、次の候補設計を絞る診断proxyである。

再現コマンド:

```powershell
.\.venv\Scripts\python.exe -m training.audit_information_loss_p6r4i
```

ローカル結果は`.tmp/training-runs/information-loss-p6r4i/report.json`、欠落マスクと原因色分け画像は同じディレクトリに保存する。

監査実装後の回帰確認は137 tests passed / 1 skippedで、`git diff --check`も合格した。実5件の再実行では全保存artifactの検証を通過し、同じ集計値を再現した。

## 解釈と制約

- 次に優先するのは、未選択の濃淡面を元画像根拠つきで補うことと、選択済み面内で空白になったセルの安全な配置回収である。
- 線回収をさらに強めるだけでは、合計79.07%を占める面候補・判定と面内配置の欠落を直せない。
- P6R-4Tの隣接面テクスチャは選択済み面の表現を分ける段階であり、面候補外の情報を復元する代用にはしない。
- この5件はv2全案不採用例に偏っており、65.10%を一般画像全体の欠落率とはみなさない。
- 相対暗度proxyは意味上残すべき背景と省略すべき背景を区別しない。回収案は追加インク量と元画像対応を制限し、人手比較を通す必要がある。

## 承認済み回収比較

2026-09-04に、同じ5件へ次の4案を出す設計が明示承認された。

1. `information-current-v4`: その入力で選択済みのv3候補を変更しない基準
2. `information-surfaces-v4`: 面候補・判定から落ちた濃淡セルだけを回収
3. `information-placement-v4`: 選択済み面内で配置されなかったセルだけを回収
4. `information-combined-v4`: 2と3の併用

元画像根拠のある空白セルだけを対象とし、4近傍で3セル未満の孤立成分を除外する。既存線被覆1%以下、基準再描画のインク被覆1%以下、対象被覆25%以上の可変幅文字区間だけを、accepted-v1で実測済みの句読点反復と余白へ置換する。置換前後のSaitamaar字幅は完全一致させる。回収セル数は基準の空白情報セルの40%以内とし、新しい線回収強化は混ぜない。

比較生成は保存済みv3をハッシュ検証し、アップロード画像と全正規化設定が一致する記録が一つだけ存在する場合に限る。v2/v3は変更せず、選択結果と全artifactは`datasets/incoming/draft-preferences/v4/`へスキーマ4で保存する。

## 実装ゲート

実5件×4案はすべて行幅完全一致、主要線損失0、元画像対応セル率100%、40%回収上限内で、安全条件に合格した。5件合計の空白情報削減率は次のとおりだった。

- 未選択濃淡面回収: 25.21%
- 面内配置回収: 3.50%
- 併用: 27.14%

事前条件の全体25%以上を未選択面回収と併用が満たしたため、実装ゲートは合格とする。個別では背景02の併用が21.02%、人物04が9.64%に留まる。全件一様な改善とは主張せず、人手比較で評価する。

最終回帰確認は、v3設定不一致の回帰テスト追加後に142 tests passed / 1 skipped、フロントエンド本番ビルド合格、`git diff --check`合格だった。

## 人手ゲート

対象は同じ5件だけで、AAの手修正は要求しない。「情報欠落回収4案」から一案または全案不採用を保存する。5件中3件以上で基準以外の回収案が選ばれた場合に合格とする。不合格なら通常生成へ接続せず、塗り量UIやP6R-4Tで情報欠落を解決した扱いにしない。

2026-09-04に5/5の保存が完了した。未選択濃淡面回収が背景02・背景06・背景07の3件、併用が人物04・人物07の2件で、基準・面内配置のみ・全案不採用は0件だった。回収案は5/5となり、事前条件の3/5以上を満たしたため人手ゲートは合格とする。

ただし、ユーザー目視では回収後にも情報欠落が残った。この5件を含む生成サンプル画像はAA化の難度が高いが、その分だけ方式間の差を評価しやすいため、ユーザー判断により差し替えずストレス評価セットとして継続利用する。この合格が示すのは難例5件内で基準より回収案が選好されたことだけであり、一般画像での十分な情報保持や通常生成への接続可否は示さない。
