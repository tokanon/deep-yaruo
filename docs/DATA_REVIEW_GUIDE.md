# 教師AAレビューガイド

## 現行レビュー: accepted-v2

画面の`教師データレビュー`は、旧317件から完全に独立した`accepted-v2`レビューを使用します。保存先は`datasets/incoming/yaruyomi/v32.1/reviews-v2.sqlite3`です。旧`reviews.sqlite3`の提示履歴、採否、カテゴリ修正、近似判定は候補選定へ読み込まず、同じAAが現れた場合も新しく判定します。旧DBと`accepted-v1`は過去実験の再現用にだけ保持します。

進捗はレビュー総数ではなく採用数で数えます。500 acceptedの最初の学習checkpointを固定・監査済みです。次の停止地点は「750 accepted以上かつ全カテゴリ最低数達成」であり、数字を揃えるためにカテゴリ不足を残したまま停止しません。その後も250件ごとの不変snapshotで監査し、750～1,000 accepted以上を想定して十分性が飽和するまで継続します。

候補は50件単位の版付きキューへ決定的に保存します。自動分類ごとのレビュー数ではなく、750件の採用構成目標に対する不足を優先し、実際のカテゴリ別採用率で必要提示数を補正します。同一MLTからの提示は通常3件までです。ただし、背景・自然のように少数の原本すべてが上限へ達しても採用最低数が不足するカテゴリだけ、原本間の提示回数を均等に保ちながら4件目、5件目と必要なラウンドまで解放します。行数、列数、文字数は順位付けだけに使い、硬い最小サイズで除外しません。v2内の完全重複と空白だけが異なる同一本文は再提示を抑止しますが、改変・派生AAは後からより良い原型が現れる可能性があるため提示対象に残します。checkpointでは近似・左右反転系列を同じsplitへ束ね、必要なら学習直前に冗長な側だけを除外します。

## 起動

通常どおりYaruo AA Studioを起動します。

```powershell
.\run.ps1
```

画面上部の`教師データレビュー`を選びます。候補は採用カテゴリの不足に応じて自動配分されます。人物だけに偏らず、顔、全身、複数人物、背景、建築、自然、小物、メカ、効果、文字から所定数を出します。成人向けも通常どおり候補へ含まれ、`SENSITIVE`は題材タグとしてだけ表示されます。

評価は`datasets/incoming/yaruyomi/v32.1/reviews-v2.sqlite3`へ即時保存します。全件索引の`index.sqlite3`とは別なので、索引を再構築しても評価は残ります。同じ本文ハッシュの完全重複は再提示されません。

## 1件ごとの操作

必須項目は採否です。採用時だけ、未分類のままにせず正しいカテゴリを指定します。

1. `採用・保留・不採用`
2. 採用時の正しいカテゴリ

完成度0～5、問題点、メモは任意です。必要な場合だけ付け、`保存して次へ`を押します。保存直後に別の未評価AAへ進みます。誤操作した場合は`直前を修正`で開き直して上書きできます。アプリを再起動しても、最後に保存した評価を同じボタンから開けます。

`別の候補`は保存せずスキップします。判断できない作品は、無言で飛ばすより`保留`として理由を残す方を優先します。

## 採否

### 採用

- 一つの完成AAとして成立している
- Saitamaar表示で行や輪郭が崩れていない
- 題材を認識できる、または構造部品として明確に利用できる
- 再描画や疑似線画生成の教師例として使える

### 保留

- 完成しているように見えるが、用途やカテゴリを判断しにくい
- 複数AA・台詞・枠を含むが、分離すれば使える可能性がある
- 一部分だけ有用、または表示条件の追加確認が必要

### 不採用

- 見出し、説明文、断片だけで単独AAではない
- 明確な位置崩れ、文字化け、切断がある
- 複数作品が分離不能な形で混在する
- 何を表すか判断できず、構造教師にも部品教師にも使えない

成人向け、古い題材、好みではない題材であること自体は、不採用理由にしません。

## 完成度 0～5

| 点 | 基準 |
| ---: | --- |
| 0 | AAではない、文字化け、完全な崩壊 |
| 1 | 断片的で、教師例としてほぼ使えない |
| 2 | 大きな整理・分離・修正が必要 |
| 3 | 標準的な完成AA。軽い修正または選別で使える |
| 4 | 線、余白、文字選択が良好で、そのまま教師候補にできる |
| 5 | 題材の整理・デフォルメ・接続が特に優れた基準作品 |

採否と点数は完全には同じではありません。例えば、完成度4でも複数AAが一塊になっていれば`保留`、完成度2でも特定の部品教師に使えるなら`保留`にできます。

## 問題タグ

- `断片`: 顔、手、線など一部分だけ
- `複数AA混在`: 一つのチャンクに独立した複数作品がある
- `台詞・枠中心`: AA本体より吹き出し、枠、説明が中心
- `位置崩れ`: 行、右端、接続が明確に崩れている
- `過密・黒塊`: 密集文字で構造が読みにくい
- `疎すぎる`: 情報が少なく題材・構造を維持できない
- `文字・ロゴ`: 人物や背景ではなく文字表現が中心
- `カテゴリ違い`: 自動分類を修正した

問題タグは不採用を自動的に意味しません。良いロゴAAなら`文字・ロゴ`を付けたうえで採用できます。

## レビュー確認点

以下は`accepted-v1`を作った旧レビューの監査履歴です。現行v2の候補順位、除外、採否には利用しません。

初回101件では採用27件、不採用74件でした。この判定を使って選定規則v2へ更新しました。次の99件では採用33件、不採用66件となり、採用率は26.7%から33.3%、平均完成度は1.07から1.69へ改善しました。一方で64 MLTからしか提示されず、一つのMLTから最大10件出る偏りが残ったため、累計200件で選定規則v3へ切り替えました。

次は50件だけ追加し、累計250件で採用率と原本多様性を再確認します。最初から125万件を全部評価する必要はありません。画面上の500件は初期レビュー全体の上限目安であり、途中の品質確認を省略する意味ではありません。

最終的に317件を確認し、採用100件、不採用217件で初期レビューを終了しました。追加の無目的な仕分けは停止し、採用100件を`accepted-v1`として固定しています。以後の再現・監査・疑似線画生成は[採用コーパスと疑似線画](CURATED_CORPUS.md)を参照してください。

## 選定規則v2

初回判定で採用された27件を落とさない範囲で、次の候補を事前選別します。

- 6～50行、最大幅50列以上、250文字以上を満たさない見出し・記号・空に近い断片・複数作を詰めた過大チャンクは提示しない
- `汎用AA/地図`、`汎用AA/体`、`汎用AA/線・図形・図表・マーク`は完成作品キューから外し、将来の部品・図表コーパス候補として原本索引には残す
- セクション名または原本名に`差分`、`省容量`、`コピー能力`を含む候補は、差分・複数作である可能性が高いため完成作品キューから外す
- 原本ハッシュを検証してから、`&#65374;`→`～`、`&#x2588;`→`█`のようなセミコロン有無の数値参照、標準の名前付き参照、MLTの疑似16進参照をUnicodeへ復元する。単独の`&`と未知の名前は変更しない
- 本文全体を復元し、文章だけでAA構造のない候補を除く
- 2行以上の空行で独立したAAを縦に連結したチャンクは、複数差分の可能性が高いため完成作品キューから外す
- 同じ原本ファイルから不採用が続いた場合は、その原本の候補順位を下げる。1件の判定だけで原本全体を禁止はしない

この選別は成人向けを除外しません。また、候補から外したレコードを削除しません。用途別コーパスを作る段階で再利用できるよう、全件索引には保持します。

`unknown`の実体は初回索引では体の部品集と図形集に集中しており、選定規則v2を通る候補がありません。このため自動層化の500件には割り当てず、画面のカテゴリ修正先としてだけ残します。

## 選定規則v3

累計200件の監査結果から、早期レビューでは同一原本内の網羅より、異なる原本・作者系列を広く確認することを優先します。

- 同じMLTから提示するAAは累計3件までとし、上限に達したMLTは初期レビューキューから外す
- 原本全体と修正後カテゴリごとの採否履歴を候補順位へ反映し、不採用が続く系列を後回しにする
- 同一MLTの既評価AAとUnicode本文を比較し、空白を除いた4文字列の重なりが94%以上で、本文長も近い候補を差分・近似重複として提示しない
- 既存200件の評価と原本索引は変更・削除しない
- 成人向けを含む題材の扱いは従来どおりで、除外せず`sensitive`タグだけを付ける

この近似判定はレビュー負荷を下げるための保守的な候補抑制です。学習・評価分割を作る段階では、左右反転、行ずれ、部分一致、別MLTへの転載も含む独立した近似重複監査を行います。
