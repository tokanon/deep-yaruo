# P1〜P6 方向性レビューの採否

検討日: 2026-08-27

## 結論

2026-08-27に提示された「方向性レビュー: P1〜P6の到達点と次の着手順」は、次の開発方向として**補正付きで採用**する。

- P6.1の低周波濃度`ch1`再校正は実施しない。
- `ch1`を画素チャンネルとして文字分類器へ投入する経路を終了する。
- 次のクリティカルパスを、濃度値の再校正から**面の表現・候補抽出・評価基盤**へ変更する。
- P4、P6、P6bと同系統の「暗い画素から塗りを決める」候補を追加しない。
- 各フェーズに停止分岐を設け、同系統の失敗が2回続いた場合は3回目の前に枠組みを見直す。

この変更は塗りや濃淡を捨てる判断ではない。画素ごとの暗さを直接「塗る理由」にするのをやめ、**色・濃度を面に属する属性として保持する**。線の字形提案`M`、面候補`G`、面の塗り判定`H`、可変幅配置`D`を分ける。

> **2026-09-07の優先順訂正:** この資料で追加した実画像修正対応対は、synthetic-to-real転移を厳密に測る任意の監査・補正手段であり、DeepAA型自己教師学習の代替でも開始条件でもない。主経路は、選別済み完成AAコーパスから線chと塗り・面chを別々に逆生成し、元AAを正解として学習することに戻す。weak-v1/v2の一枚合成とP6の低周波`ch1`の失敗を、分離逆生成経路全体の棄却根拠にしない。

```text
入力画像 ─→ 線抽出 S_line ───────────────┐
       └→ 面候補 G ─→ 面属性 ─→ 塗り判定 H ├→ 制約付き配置 D → AA
完成AA ─→ 文字・開始位置教師 ─→ 字形提案 M ┘
       └→ 反復塗りrun ─→ AA塗り面ラベル
```

## 採用する指摘

### 1. 水平runを二次元の塗り面へ束ねる

`training.aa_fill_layers.detect_fill_runs()`は、Saitamaarの実advanceを持つ行単位の`FillRun`を返し、隣接行の重なりも`vertical_support`の判定に使っている。しかしrunを複数行の面へ束ねていない。

隣接行かつ水平重なりがしきい値以上のrunを連結し、同一面ID、外接矩形、面積、行数、run数、使用文字と濃度段階を持つ`FillSurface`へ変換する。最初は1行差だけを接続し、分割・併合と複数文字網掛けを別の未対応項目として記録する。

### 2. 実画像で色と閉領域を面候補に使う

現行`backend.image_io.decode_image()`は読込時にグレースケール化するため、イラストの色領域を利用できない。既存のグレースケール実行経路は壊さず、実験用に色を保持する読込経路を追加する。

- イラスト・原画: Labなどの知覚色空間で量子化し、連結成分と隣接関係から候補面を作る。
- 線画: 元線を変更せず、面検出専用バッファだけClosingとflood fillを行い、外部背景を除いた閉領域を候補面にする。

どちらも**候補面**であり、検出しただけで塗り対象にしない。顔、白目、肌、空などの非塗り面を含むことを前提にする。

### 3. 面単位の評価を第一級にする

塗りの評価では、画素accuracyや反復run内`charAcc`だけでなく、面の対応を記録する。

- 対応面のIoUと被覆率
- 塗り面precision / recall
- 過剰塗り面数、欠落塗り面数
- split、merge、境界漏れ
- 面内の線損失
- 面ごとの塗り文字・濃度段階の一致

固定4画像は回帰スモークに限定し、採用判定は線画以外を人物・背景各10枚以上含む未学習集合で行う。

### 4. 停止条件を明示する

各ゲートは次の3分岐を持つ。

1. 合格して次へ進む。
2. 不合格だが、原因が局所設定と確認でき、事前に定めた別候補へ進む。
3. 前提否定、原因不明、または枠組みの失敗として停止し、結果を報告する。

目視棄却は「設定」か「枠組み」かを記録する。同系統の失敗が2回続いたら、新しいパラメータ候補を追加せず枠組みを再検討する。

## そのままでは採用しない記述

### 1. 64×64 CNNに面を表現できないとは断定しない

64×64の受容野を持つCNNは局所領域を暗黙に表現できるため、「チャンネルである以上、面を扱えずP4/P6の失敗は必然」とまでは証明されていない。正しい判断は、**現行データ・入力定義・損失・評価では面の対応を学べなかったため、明示的な面表現を次の検証対象にする**ことである。

### 2. AAの塗りrunは確定情報だが、元画像との対応は確定しない

反復文字は「その完成AAで作者が塗り表現を使った」ことの確定ラベルである。一方、その面が元画像のどの色領域・閉領域に対応するかは、対応画像なしには分からない。`accepted-v1`のAA単体から得られるのは出力側の正例、語彙、面形状、配置事前分布である。

さらに、反復塗り面だけでは「塗らない面」の負例がない。二値分類器を作る場合は、AAラスタ側でも閉領域などの**全候補面**を抽出して反復塗りとの重なりから正負を付けるか、元画像・修正AA対応対からラベルを作る必要がある。

### 3. 未対応集合では正しさのIoUを計算できない

P1参照30枚と`accepted-v1` 100作品は別々の作品であり、画素対応するgold対ではない。両集合の面数、面積、位置、色・濃度分布は比較できるが、面IoU、過剰塗り、欠落塗りという**正誤**は計算できない。

用途を次のように分ける。

| データ | 測れること | 測れないこと |
| --- | --- | --- |
| AA単体 | run→面の整合、面数・面積・語彙分布 | 実画像のどの面を塗るべきか |
| 未対応の実画像30枚 | 候補面の数・面積・境界漏れの診断 | 正しい塗り面IoU、過剰・欠落 |
| AA由来合成 | 同一座標上の面検出・分類回帰 | 実画像での線選択と意味対応 |
| 元画像＋人手修正AA | 同一座標上の面IoU、過剰・欠落、修正量 | — |

### 4. 色量子化と閉領域は意味領域そのものではない

色の微妙な差による過分割、同色の別物体の結合、開いた輪郭からのflood fill漏れ、穴・入れ子・外部背景が起きる。候補生成では複数粒度、隣接グラフ、面積範囲、外周接触、split/merge診断を持たせ、単一しきい値を正解としない。

### 5. tone情報は面属性として残す

打ち切るのはP6の`ch1`入力経路であり、濃淡情報そのものではない。各候補面について平均・分散・分位点、周辺面との色差、局所コントラストを保存し、塗るか、どの濃淡文字を使うかの特徴へ使う。線画ではtone属性を欠損として扱い、存在しない濃淡を推定しない。

## 改訂後の着手順

### P6R-1: AA塗り面

- `FillRun`を隣接行の重なりで`FillSurface`へ連結する。
- 可変幅座標、行ピッチ、面積、外接矩形、文字構成を保存する。
- `accepted-v1` 100作品で面数・面積・高さ・語彙分布を出す。
- **合格**: 同じrun集合から決定的に同じ面が得られ、描画した面マスクと面積集計が一致する。
- **停止**: 反復塗りが面としてほとんど連結せず、複数文字網掛け未対応が主要例を支配する。

2026-08-27に実装・全100件集計を完了した。2,535 runから656面を得て、2,347 run（92.584%）が複数行面へ入り、面マスク画素数と面積集計は全件一致した。停止条件には該当せず合格とする。反復runなし22作品と複数文字網掛けは未対応として残す。詳細は[P6R-1資料](AA_FILL_SURFACES_P6R1.md)に固定する。

### P6R-2: 面指標と対応条件

- 同一座標の2面集合を最大IoUなどで一対一対応させる。
- IoU、precision/recall、過剰、欠落、split/mergeを実装する。
- 未対応集合へ正解指標を出さない契約とテストを追加する。
- **合格**: 合成した完全一致、過剰、欠落、split、mergeの各ケースを区別できる。
- **停止**: 可変幅AAと入力座標を一意に対応できない。

2026-08-27に実装・固定確認を完了した。完全一致、過剰、欠落、split、mergeの5合成ケースを区別し、面内線損失も計算できた。accepted-v1全100件・656面の自己回帰は全件一致し、対応IDを持たない同じ100件は全件評価拒否した。停止条件には該当せず合格とする。詳細は[P6R-2資料](SURFACE_METRICS_P6R2.md)に固定する。

### P6R-2S: 修正対応対の保存基盤

P6R-2の座標・面契約を確定した直後へ前倒しする。元画像ハッシュと来歴、クロップ、全変換設定、抽出線、草案AA、修正AA、Saitamaar再描画、座標変換、文字差分を、スキーマ版付きの一組としてローカル保存・再読込する。P6R-3の候補面方式を待たずに修正対を蓄積でき、後から候補面と面対応を同じ記録へ追記できる形式にする。

- **合格**: 保存直後と再読込後で全ハッシュ・設定・テキスト・座標変換が一致し、同じ入力と設定から草案AAを再生成できる。
- **停止**: 変換条件または座標変換を再現できず、候補面・修正AA面を同じ記録へ安全に追加できない。

2026-08-28に実装・固定確認を完了した。スキーマ版付き不変manifest、全artifactハッシュ、実クロップと順逆座標変換、文字差分、草案再生成照合を実装し、P6R-3/4の面情報はrevision付き`extensions.json`へ原子的に追記できる。改変検知、冪等保存、再読込、拡張後のmanifest不変をテストし、停止条件には該当しないため合格とする。詳細は[P6R-2S資料](CORRECTION_PAIRS_P6R2S.md)に固定する。

### P6R-3: 実画像の候補面

- 色保持読込を追加し、既存グレースケール経路を回帰させる。
- イラストの色領域と線画の閉領域を別実装し、共通`SurfaceProposal`へ正規化する。
- P1参照30枚では候補面の分布と境界漏れを診断し、正解IoUは主張しない。
- **合格**: 人が重要と判断する髪・服・背景面または線画閉領域が候補集合に含まれ、外部背景への漏れを診断できる。
- **停止**: 古典処理で主要面を候補へ載せられない。学習済みsegmentationの導入可否をその時点で判断する。

2026-08-28に実装・P1参照30件の固定診断を完了した。既存グレースケール経路を保った色読込、Lab `4×4×4` / `6×6×6`の色連結領域、検出bufferだけへ3px / 5px Closingを掛ける線画閉領域、外部背景除外、共通面属性、隣接・粒度間split / mergeを実装した。全30件に候補があり、目視で主要な顔・髪・服・背景色面と線画閉領域が候補集合へ入った。写真の断片化、淡色面の融合、開いた輪郭の欠落をP6R-4へ引き継ぐ条件付き合格とする。未対応集合なので正解IoUは算出していない。詳細は[P6R-3資料](SURFACE_PROPOSALS_P6R3.md)に固定する。

### P6R-4: 対応対と塗り判定

- P6R-2Sで保存した元画像、草案AA、人手修正AA、座標変換へ候補面と面対応を追記する。
- 最初は規則ベースで面の塗り有無と濃淡文字を決める。
- 規則が基準を超えない場合だけ、小さな分類器を同じ面特徴で比較する。
- **厳密な対応付き品質ゲートを実施する場合の合格**: 人物・背景の未学習対応対で、C1基準より過剰・欠落・面内線損失と人手評価を改善する。必要件数は目的と負担を含む別チェックポイントで定め、逆生成学習の前提にしない。
- **停止**: 候補面と修正AA面の対応が安定せず、規則と分類器のどちらも同じ失敗へ収束する。

2026-08-28に対応・保存・規則ベース評価の基盤を実装した。保存済み実クロップとAAキャンバスへP6R-3候補面を合わせ、修正AAのP6R-1反復塗り面との全重なり、規則判断、P6R-2指標を三拡張スロットへ一回で保存できる。色の合成対応対は完全一致し、線画はtone欠損としてabstainする契約を通過した。実修正対応対0件のため、この基盤による厳密な実画像面品質ゲートは未評価のまま保持する。ただしこれは保存・監査機能の状態であり、accepted-v2からの線・塗り分離逆生成とDeepAA型再学習を停止させない。正解対応なしではsynthetic-to-real gapを切り分けられない例が生じた場合だけ、少数を任意収集する。詳細は[P6R-4資料](SURFACE_DECISIONS_P6R4.md)に固定する。

### P7以降

線の文字候補、実幅保持配置、接続、n-gram、2D探索は面判定と独立して比較できる。P6Rの面判定は、画素マスクで直接上書きしたP4とは別設計として線候補を境界・内部で拘束する入力へ接続する。実幅保持処理の根拠は後のP6R独立テストに限る。P6の画素`ch1`は再開候補にせず、accepted-v2から塗り・面chを別設計する。

## 保持する成果

- P0のレンダラ逆検証と可変幅座標
- `training.aa_fill_layers`と`backend.aa_semantics`
- P1の共通幾何と線抽出コード
- `accepted-v1`、MLT単位split、来歴・漏洩監査
- P2〜P6のコード、数値、失敗結果
- 後のP6Rで行幅・線保護を独立検証した実幅保持配置。P4の結果自体は採用根拠にしない
- 実行時の塗り文字反復ペナルティ免除

## 外部候補の扱い

提示書にある顔検出・segmentation候補は、P6R-3の古典処理が停止条件に達した場合の比較候補に留める。現時点では依存・重み・ライセンスを採用しない。実際に導入するときは、コードだけでなく重み、学習データ由来、再配布条件を公式配布元で再確認し、`THIRD_PARTY.md`と`models/README.md`へ固定する。

2026-08-27時点の公式表示では、`lbpcascade_animeface.xml`自身にMIT条文、OpenCV ZooのYuNetモデルディレクトリにMIT `LICENSE`、SkyTNTのコードリポジトリとHugging FaceモデルページにApache-2.0表示がある。`siyeong0/Anime-Face-Segmentation`はリポジトリがMITで、`UNet.pth`も同じリポジトリに置かれているが、READMEから学習データ・重みの来歴を確認できない。したがって提示書の「導入候補」という分類は妥当だが、どれも現段階の採用資産にはしない。
