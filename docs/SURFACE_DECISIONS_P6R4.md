## 面制約付き塗り4案

`backend.surface_fill`と`POST /api/surface-fill-comparison`は、同じ設定のDeepAA/Beam基準案を一度だけ生成し、次の4案を元画像内容の安定ハッシュ順で候補A～Dへ割り当てます。

| 内部variant | 面判定 | その他の条件 |
| --- | --- | --- |
| `surface-fill-none-v2` | 無塗り | DeepAA基準案そのもの |
| `surface-fill-conservative-v2` | score 0.30 | 相対濃淡別の保守配置 |
| `surface-fill-standard-v2` | score 0.30 | 相対濃淡別の標準配置 |
| `surface-fill-expanded-v2` | score 0.30 | 相対濃淡別の拡張配置 |

3つの塗り案はすべて`lab-l4-a4-b4`候補面とscore 0.30を使います。クロップ内有効画素のグレースケールP10/P90から各面の相対的な暗さを求め、dark（0.67以上）、middle（0.33以上）、lightへ分けます。絶対的な暗さは塗り文字の濃度選択に残すため、全体が淡い画像でも相対的に暗い面を拾いつつ、出力文字を一律に濃くしません。P4のグローバル`ch2`判断は使いません。

| 案 | dark 面被覆/安全域/構造上限 | middle | light |
| --- | --- | --- | --- |
| 保守 | 70% / 50% / 6% | 80% / 60% / 4% | 90% / 70% / 2% |
| 標準 | 60% / 40% / 8% | 70% / 50% / 6% | 80% / 60% / 4% |
| 拡張 | 50% / 30% / 8% | 60% / 40% / 6% | 70% / 50% / 4% |

境界余白1px、3文字以上の連続は共通です。拡張案は面被覆と安全域だけを緩め、構造上限は標準と同じにして線損失を抑えます。各行のSaitamaar advanceが変わる置換は拒否します。線画プロファイルはtoneがないため比較対象外です。

`POST /api/surface-fill-preferences`は、比較種別、生成器版、recipe版、共通設定・クロップ・抽出線、各候補の面設定・判断・塗りマスク・置換診断・再描画、選択または全案不採用を、`datasets/incoming/draft-preferences/v2/`へ不変・冪等保存します。旧line設定4案のv1記録は保持しますが、このパイロットやP6R-4品質証拠には数えません。

初回`surface-fill-v1`は固定配置条件が厳しく、3件中2件で標準案が0置換だったため停止しました。`surface-fill-v2`の実装ゲートでは、同じ3件で保守／標準／拡張の置換元セル数が人物1で633/712/733、人物2で131/172/182、人物3で224/307/354となりました。標準は全件非ゼロで塗り量は全件単調増加、主要線損失は全候補最大1.6883%、全行幅差0でした。これは実装確認であり人手品質評価件数には含めません。

## 実装

`backend.surface_decisions`はP6R-2Sの不変記録を読み、次を一回の拡張更新として保存します。

1. 保存済み元画像を色保持で読み、実クロップをAAキャンバス寸法へ変換する。
2. P6R-3の色領域または線画閉領域を同じAAキャンバス座標で生成する。
3. 修正AAからP6R-1の反復`FillRun`と`FillSurface`を抽出し、正解側ラベルとする。
4. 各候補面と修正AA塗り面の全重なりを、IoU、双方の被覆率、split / merge診断用の対応として保存する。
5. 透明な規則ベースv1で候補ごとに`fill`、`reject`、`abstain`と濃淡段階を出す。
6. P6R-2の一対一面指標で、同一`correspondence_id`・`coordinate_space_id`上の結果を評価する。

三つの拡張スロットの役割は次のとおりです。

| スロット | 内容 |
| --- | --- |
| `surface_proposals` | 入力候補面、属性、ラベルspan。候補であり塗り確定ではない。 |
| `surface_correspondence` | 修正AA反復塗り面、ラベルspan、候補との全重なり、人物・背景層。 |
| `surface_metrics` | 規則設定、候補ごとの判断理由、予測ラベル、面・画素・split / merge指標。 |

更新は三スロットをまとめて`CorrectionPairStore.update_extensions()`へ渡します。10 MB制限は更新差分だけでなく、更新後の拡張データ全体へ適用します。`record.json`と既存artifactは変更しません。

## 規則ベースv1

色候補面では次の説明可能な特徴だけを使います。

- 面の平均輝度から求める暗さ
- 周辺ringより暗いかを表す符号付き輝度差
- 周辺とのLab色差
- compactness
- 画像外周接触への減点
- 面積50%以上の広域面への減点

固定重みのscoreが0.45以上なら`fill`とし、暗さから0～3の濃淡段階を付けます。これは比較下限であり、実画像対応対を見て調整済みの規則ではありません。

線画候補面には元来のtone属性がありません。P1〜P6方向性レビューの契約どおり濃淡を推定せず、v1は全候補で`abstain`します。これにより、閉領域を検出しただけで一律に塗る旧P4型の誤作動を避けます。

修正AA側の正解面は同一文字の反復塗りだけです。複数文字網掛けは未対応なので、修正AAの全塗り表現を網羅するgoldではありません。

## APIと集計

- `POST /api/correction-pairs/{record_id}/surface-analysis`: 保存済み一件を解析し、三拡張スロットを原子的に更新する。
- `training.evaluate_surface_decisions_p6r4`: 全記録を読んで人物・背景層、候補数、修正AA面数、規則ベース指標を集計する。既定は読取評価だけで、`--write-extensions`指定時だけ各記録へ保存する。

人物・背景は変換時の明示プロファイルから層化します。`person` / `lineart`は人物、`background` / `background_lineart`は背景、`auto`はunknownです。これは題材を画像認識したラベルではなく、生成条件の来歴です。

## 合成回帰

- 左半分が暗色、右半分が明色の同一座標対では、暗色候補1面を`fill`、明色候補1面を`reject`とし、面precision / recall、画素IoUはいずれも1.0になりました。
- 線画閉領域と修正AA塗り面の対では、候補を検出しつつ規則v1は`abstain`し、欠落1面として評価しました。これは濃淡欠損時に推測しない契約の回帰です。
- 修正対応対へ保存した場合、三スロットが同じrevisionで更新され、ベース`record.json`はbyte単位で不変でした。
